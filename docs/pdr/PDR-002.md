# PDR-002: Why Deterministic Citation Faithfulness Alongside Ragas

## Context

As of Q4 2024, BrandGuard AI faced a critical architectural choice in its release gate strategy. The product had adopted ragas (a framework for evaluating retrieval-augmented generation systems) as a quantitative metric for measuring citation quality. Simultaneously, the team recognized that deterministic checks (file existence, anchor validity, schema conformance) could provide a complementary safety mechanism.

The decision emerged from two competing intuitions. First, LLM-judged metrics like ragas offer flexibility: they can evaluate whether citations semantically match claims, tolerate paraphrased content, and score citations on a continuous scale. Second, deterministic checks provide absolute guarantees: a citation either exists in the source or it does not. No variance, no hallucination risk at the gate itself.

The governance requirement was clear from [DJ-002], which established that brand voice adherence must be deterministic wherever possible. [DJ-003] reinforced this principle specifically for citations and brand messaging. The evaluation split defined in [DJ-008] separated training data from holdout test data, creating a natural fork where citation strategy could be tested independently. [DJ-006] documented the P22 (Priority 22) incident, where missing citations undermined trust in a Strand Wireless campaign output, even though the claims were factually sound.

## Decision

BrandGuard adopts a two-layer citation assurance model:

1. **Deterministic Layer (gate enforcement)**: All citations must pass automated existence checks before any LLM evaluation occurs. This includes file-path resolution, anchor anchor validity (matching [DJ-NNN], [ADR-NNN], [brand_voice:§N] patterns), and schema conformance. Failure at this layer blocks release.

2. **LLM-Judged Layer (observability and tuning)**: Ragas metrics measure semantic alignment between claims and cited sources. These scores inform product quality signals and guide fine-tuning, but do not directly gate releases.

The deterministic layer runs first and is mandatory. The LLM layer runs second and is informational. This ordering ensures that no citation can reach production if its target does not exist, regardless of how well an LLM judges the semantic match.

## Trade-Offs Considered

### Ragas-Only Approach

Advocates noted that ragas-style evaluation tolerates paraphrased content, awards partial credit for near-hits, and aligns with how humans evaluate citation quality. Drawbacks: LLM scoring introduces variance across runs, paraphrase tolerance can mask fabrication (an LLM might score a plausible but false claim highly if it resembles real content), and the gate becomes opaque to auditors (a 0.87 ragas score is harder to defend than a file-existence check).

### Deterministic-Only Approach

Pure deterministic checks guarantee no fabricated anchors reach production. Drawback: they cannot catch semantic drift (e.g., a claim that slightly misrepresents the cited source), cannot reward partial correctness, and fail on ambiguous citation styles (e.g., should a paraphrased Strand Wireless policy be cited by policy name or exact section number?).

### Hybrid (Chosen)

The deterministic layer prevents the worst failure mode (nonexistent citations). The LLM layer provides nuance and aligns with how stakeholders actually judge citation quality. The separation of concerns means the gate remains auditable (deterministic pass/fail) while the observability layer remains flexible (continuous scores).

## Foreclosed Paths

This decision rules out:

- Treating ragas scores as sufficient release criteria. A 0.95 ragas score does not override a missing file.
- Allowing citations with graceful degradation (e.g., "if anchor not found, skip it"). Citations either exist or they do not.
- Deferring citation validation to post-release monitoring. The gate must block, not warn.
- Using LLM evaluation as the sole truth source for citation correctness. LLMs can be confident and wrong.

## Consequences

### Immediate

The deterministic layer adds 40-80 milliseconds of latency per release gate execution (file I/O and regex validation). Documentation and citations in Strand Wireless collateral must follow strict anchor patterns (DJ-NNN, ADR-NNN, brand_voice:§N, fact_sheet:SKU:field) or they will be rejected. Authors cannot use ad-hoc citation styles.

### Medium-Term

Ragas scores will accumulate as a quality signal over 6-12 months. This data will inform whether the LLM layer catches errors the deterministic layer misses. If ragas consistently flags valid citations as low-quality, the scoring model will require retraining.

The deterministic layer becomes a contractual obligation: Strand Wireless can trust that any citation in a BrandGuard output points to an actual resource. This simplifies audit responses and customer support escalations.

### Long-Term

The two-layer model creates a foundation for progressive enforcement. In future versions, the LLM layer could be promoted to a soft gate (advisory warnings) if variance is reduced. Conversely, if the deterministic layer proves sufficient, the LLM layer could be deemphasized in favor of pure offline analysis.

## On The LLM-Judged Score Defense

Stakeholders sometimes argue that ragas scores should directly gate releases, pointing to high scores as evidence of quality. This framing is incorrect.

The deterministic safety floor is the strong story. It answers the audit question: "Is this citation real?" with a binary, verifiable answer. Deterministic checks cannot hallucinate, cannot be confident and wrong, and do not vary across runs or model versions.

LLM-judged scores describe LLM behavior, not gate efficacy. A 0.92 ragas score means the language model believes the citation aligns with the source and the claim. It does not mean the gate will not fail, because the deterministic layer operates independently. A 0.92 score alongside a missing file is a failed release. The score is useful for understanding why the failure occurred (the LLM thought it was good) and for training future versions, but it is not a substitute for file existence.

The two layers answer different questions:

- Deterministic: "Does this citation point to something real?"
- LLM-judged: "Does this citation make semantic sense?"

Both questions matter. Only the first one should block a release.
